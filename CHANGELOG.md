# Changelog

The analyzers package, the `fsharp-refactor` tool and both editor extensions share one version. The NuGet packages carry the notes of the last 6 versions; this file keeps every one.

## 0.8.20

Three idiom rules. FR0158 (new) turns a while loop that walks a mutable index while a condition holds - `let mutable line = 0` then `while line < max && blank line do line <- line + 1`, or the countdown - into a tail-recursive local function (`advanceLine` / `retreatLine`) and an immutable `let`; measured level with the loop, where the Seq.tryFind spelling doubled the time and allocated per call. FR0156 (new) turns a ResizeArray that loops fill one Add at a time and the rest of the scope only reads into a list expression: the loops (for and while alike) move inside the brackets as they are - guards, matches, nested loops, lets and the statements around each Add included - and each Add becomes the implicit yield of its argument; List.ofSeq acc becomes acc, and Seq functions, for x in acc and an upcast to seq keep working. Measured in PerfClaims (.NET 10, 1000 ints): 20 percent faster on 30 percent less allocation than the fill-then-copy. A drain that wants an array (an index, Count, ToArray(), Array.ofSeq) stands the rule down, since the array expression measured 1.6x the ResizeArray fill's time and ResizeArray plus ToArray() is the fastest spelling of an array built one element at a time; { "FR0156": { "arrays": true } } buys the shape at that price. The declared element type becomes the list's annotation (Add converted an int literal to int64 through the method call where a bare yield would not), and an element type with subtypes to upcast from (an interface, obj, an unsealed class) stands the rule down. FR0157 (new) turns a closed set of string literals matched by name into a [<RequireQualifiedAccess>] union with a ToString returning the original text. The proof is a flow analysis over the string slots the value passes through - a parameter, a let, a record field, a function's return, a name a pattern binds, plain or option-wrapped - closed when every source is a literal (or a constant, [<Literal>] or not) or another slot and every sink a match, a comparison with a literal, a flow into a slot or a print through ToString; proven from either end, the call sites or a producing function whose every exit is a literal. Every literal source, arm and comparison becomes its case, every annotated slot is retyped, and a catch-all the proof leaves dead is dropped - it stays where the proof found a literal no arm names. A variable pattern spelling a module-level constant's name beside later arms (| us -> under let us = "...", which binds a fresh us and matches everything) is taken for the comparison the author meant, and the message says so. A Result<_, string> is a slot like the others: its Error "..." exits are sources, its Error "..." arms the consumer, the Ok side is not followed. Under --api-changes the apply tool's api pass runs the rule with every referencing project's call sites in its world, so an exported function's literal callers count; where the host still cannot see every caller, the exported function keeps its public signature behind an adapter - a private twin typed with the union, the compilation's own callers moved to it, a wrapper of the old name mapping at the edge (OfString, whose unknown arm is the match's own raising catch-all; Result.mapError string) under a TODO. A %s hole becomes %O and a concatenation operand `string x`; a sentence-shaped literal keeps its words behind double backticks; a record a serializer fills ([<CLIMutable>], a Json or DataContract attribute, the type as a type argument anywhere), a dynamic message, a method call on the string, a function used as a value, a lambda parameter, and a set no producer feeds stand the rule down. The apply tool reads the whole compilation's symbol uses once, indexed by declaration and by position, so the analysis costs a few seconds per project rather than a walk per question. FR0154 is a correctness rule now and rewrites only the miss arm: TryGetValue then a store on a ConcurrentDictionary keeps its match and hit arm, and the miss arm becomes GetOrAdd(key, fun _ -> compute ()), whose add is atomic. Measured at tier 1 the hit path - the one a cache takes almost every time - is 2.1 ns and nothing on TryGetValue against 7.3 ns and a 64 B delegate on GetOrAdd, so the whole-match rewrite of 0.8.12 was a slowdown sold as a speedup; the race it closes is the reason, and this shape closes it at no cost. Where running the factory ONCE matters, GetOrAdd alone does not buy it (concurrent misses each run it), so a factory that calls something carries the hint that a Lazy value - GetOrAdd(key, fun _ -> lazy (compute ())).Force() - runs it once, and a Task, ValueTask or Async value, where the discarded result is a computation already running, gets that note without a fix.

## 0.8.19

The build configuration the analysis does not see is no longer a blind spot. A project whose sources branch on `#if DEBUG` / `!DEBUG` / `RELEASE` / `TRACE` gets a second pass under the other configuration, where those branches are the parse tree, and its verification builds both configurations; a referencing project edited by a call-site migration is built in the other configuration too, and the migration is put back when that build fails. A call-site migration (FR0090, FR0091) keeps back a function named inside a configuration region, whose other branch has calls no parse tree holds, and one a string literal names anywhere in the project or its referencing projects - a code generator's template writes calls no symbol table lists (SQLProvider.Fable's CodeGen kept emitting the old parameter order after FR0091 reordered Row.text). The apply tool withholds any multi-line fix whose span covers a #if, #else or #endif line, whatever rule offered it.

## 0.8.18

A sweep spends far less of its time in MSBuild and FCS. The compiler-argument query no longer cleans the project (a design-time build with the target forced, in place of the Rebuild that cleaned the outputs and cost a third build to put them back), and the FS3511 harvest that made every compilation recompile is cached per source tree under the local application data, so an unchanged project builds incrementally in a second or two - 28 seconds of fsc per compilation on FunStripe.Core gone. A multi-targeted project builds every framework in one parallel outer build on its narrowest pass, and the next framework's compiler arguments and typecheck run ahead on a checker of its own while the narrower pass sweeps: FCS keeps one incremental builder per project file name, so the frameworks were throwing each other's typecheck away at every switch and could never share one; the second framework's check now costs milliseconds. A file whose only conditional directives are INTERACTIVE or COMPILED - the idiom for a source that also serves as a #load'ed script - is swept once across frameworks like a directive-free file, since neither symbol varies between a project's frameworks. A script's sweep leaves the #load'ed sources a project compiles to that project: Owin.Compression's Script.fsx, typechecked as .NET Core, had written Convert.ToHexString and File.ReadAllBytesAsync into the net48 project's CompressionModule.fs. A proposed FR0155 ([<Sealed>] on internal classes) is benchmarked in PerfClaims before being written: the covariant array store halves and the type test does better, the virtual call does not move.

## 0.8.17

A test project's declarations reshape without --api-changes: a project that references xunit, NUnit, MSTest or Expecto exports no API, nothing links to it, so FR0090, FR0091, FR0069, FR0093 and FR0049 treat its own functions as they treat a private module's, while the library compiled after it finds the gate closed again. The project's own type providers are instantiated before any `#r` script is read against a .NET Framework reference set: FCS keeps a design-time assembly by name, welendus's Program.fsx `#I`d packages/FSharp.Data/lib/net45, and every project's JsonProvider was "not defined in 'FSharp.Data'" from then on - four projects skipped in a tree that builds. FR0147 checks every bare name the file uses against what an open brings, not only the uppercase ones: an `[<AutoOpen>]` module brings its VALUES with the namespace, and `open Lib` placed below `open Other.Z` rebound a `helper 4` from Z's to Lib.Auto's, compiling and answering differently; a name resolving to a local is no clash (a local shadows the open wherever it sits); and a union case matched by its qualified spelling (`| Lib.Kind.A ->`) is shortened with the expressions, when it resolves to a case. FR0094 keeps the parentheses inside a `_.` shorthand lambda, as FR0013 did: `configureEndpoint _.WithName("x").WithGroupName(g)` bare applied the lambda to `g`. FR0029 leaves a `return (* note *) value` in place for the plain closure: without the keyword the line's first token stands right of the comment, and the parser reads it as the previous let's continuation. FR0035 asks the typed tree whether a list's element type satisfies `comparison` before turning the list into a `Set`, and offers the HashSet companion (equality only, which `List.contains` already asked) where it does not - a [<NoComparison>] record, one with a function field. A rewrite that fabricates a closure or a computation expression asks the typed tree whether the code it moves reads a byref or byref-like value - a Span, a ReadOnlySpan, a [<IsByRefLike>] struct of the project&apos;s own - which no closure may capture and no task { } may hold: FR0034&apos;s Option.exists lambda, FR0009&apos;s Result lambdas, FR0029&apos;s runTail, FR0142&apos;s task-returning test and FR0049&apos;s taskify all stand down where one is in reach (FR0154 already did; the check is shared now). FR0142 no longer holds a test back for a `static let mutable` of its OWN class: xUnit, NUnit and MSTest run one class&apos;s tests one after another whatever they return, so the order CarmelNet&apos;s tests rely on - one writes a payment id, the next reads it - survives the rewrite; module-level state and another class&apos;s still do. A typecheck that never returns is abandoned after 15 minutes (FSREF_CHECK_MINUTES raises it) and the compilation reported and skipped rather than the run waited on: SQLProvider&apos;s DuckDbTest.fsx sat in its type provider&apos;s database connection for two and a half hours.

## 0.8.16

Three more from the same re-sweep, each rolled back by the build check and put right at the source. FR0034 spelled a backticked option bare - `match in 24h cooling-off FCA period with` (welendus's SignalRHubs.fs), where `24h` is a numeric literal - and now spells the option as the source does, with a plain `value` binder where `<x>Value` would carry the spaces. ## 0.8.15

Three defects found by re-running the 0.8.14 sweep over the C:\git repositories beside the 0.8.13 results. The apply tool's alignment backstop (and the FR0094/FR0013 check it shares, Text.alignmentHazard) asked only whether the next line stood at or past the edit's end, which is every arm body under a `| _ ->` FR0072 would expand and every argument continued on the next line: it silently withheld all ten wildcard expansions in management-portal's hubs and, held at message level, all 63 FR0147 edits of ClearBank.Net's tests for one continued call. FR0092's test-side loosening ran on its own turn for any literal a production `failwith` spelled, read off raw text: a `failwith "Error"` in a doc comment had this repository's own `Assert.Equal("Error", s.LogMethod)` turned into StartsWith with nothing enriched anywhere. The loosening now rides in the production message's own fix as cross-file edits (one atomic set, read fresh from the test file), and only an assertion on an exception's `Message` is loosened - one spelling the text about anything else vetoes the enrichment. FR0142 shifted the continuation lines of a `let` whose expression starts on the line below by the `!` it added, where those lines stand relative to the `let` itself: FunStripe's tests came out with their bodies one column deeper than the block's head.

## 0.8.11

FR0147 declines an `open` on the mechanism rather than by namespace: a fresh open that brings an extension member named like a method the file calls with a tupled argument - `seen.Contains (e, ct)` under `open System.Linq`, where F# hands the tuple to `Enumerable.Contains(value, comparer)` as two arguments - is noted, never inserted, and the same check holds for a project's own extension namespace (reproduced with a hand-written one: the identical FS0001). The file's tupled calls are collected once and the namespace's extensions only when there is a call to match them against, so an already-open namespace costs nothing. FR0092 leaves a `failwith` alone when a test asserts its exact text - the enrichment would have turned that test red - and under --api-changes enriches it and loosens the assertion to a prefix match in step (FsUnit `should equal` becomes `should startWith`, xUnit `Assert.Equal` becomes `Assert.StartsWith`). FR0015 counts a lambda handed to a List/Seq/Array function as the loop it is (LoopPerf.loopBinders, shared with the other loop rules) and hoists a Regex CONSTRUCTED with a literal pattern out of a loop or such a lambda - `Regex("lit")`, `new Regex("lit", RegexOptions.IgnoreCase ||| RegexOptions.Multiline)`, the qualified spelling - moving the construction's own source text to a `let private xRegex =` binding above the enclosing declaration and replacing only the construction, so a `let regex = Regex(";([a-z]*)=")` followed by `regex.Split(v)` (FSharp.Analyzers.SDK's expandMultiProperties, hoisted by hand in commit 6dd6679) becomes `let regex = azRegex` with the Split untouched; declined for a non-literal pattern, options naming a local or a multi-line construction, where FR0037's "Regex built in a loop" note keeps firing - and stands down where FR0015 fixes. The hoisted binding lands above a plain `//` comment block describing the declaration as well as above its `///` doc, never between either and the `let`. --api-changes now rewrites call sites in the SIBLING PROJECTS of the same solution: a public tupled function (FR0090) or data-first pair (FR0091) is reshaped together with its calls in every project of the run that references it - the test project, typically - each such project typechecked against the library sources in memory, its uses matched by declaration and its files edited in the same atomic set as the definition, then typechecked again before the edits stay; a referencing C# or VB project, a sibling that does not typecheck, a script #r-ing the built assembly, or a bare project run with no solution above it that lists it holds every public function in its present shape and says so once per project. An internal function of an assembly with InternalsVisibleTo friends now waits the same way for every friend to be read, where before the friend was never consulted. A cross-file suggestion that could apply in one file but not another is put back whole rather than left half-applied.

## 0.8.10

FR0085 no longer strips a `new` whose bare name would be captured by a FUNCTION. `new string(chars, i, n)` became `string(chars, i, n)`, which is FSharp.Core's conversion applied to a TUPLE and yields the literal "(System.Char[], 1, 12)" - management-portal's id generator handed that out as every id and its uniqueness test failed, all of it typechecking cleanly so no build check could see it. Three guards now: FSharp.Core's conversion names, a value declared in the type's own module, and any function an `open` in the file brings into scope; each was reproduced on a running probe before being fixed. FR0029's tail extraction ADVISES by default and fixes only under { "FR0029": { "extractTail": true } }: `runTail` names no business idea, and a smaller resumable body is not a goal in itself - only FS3511 makes it one, and FS3511 is emitted at codegen where no analyzer can see it. Hoisting plain lets and splitting branches move code that already existed, name nothing new, and stay fixes. The return hoist gained three guards of its own, each measured rather than assumed: a `use` inside the branch (the builder's Using becomes the language's, DisposeAsync silently becoming Dispose), a directive block opening on the line below it (another configuration may hold arms this one cannot see), and the emit no longer leaves `return` alone on its line or duplicates a trailing brace. A tail closing on a bare `return` now extracts as a plain closure instead of gaining a second task builder. New knob { "FR0029": { "hoistReturnOnAsync": true } } extends ONLY the return hoist to async, worth about 27 percent less generated IL on a twelve-arm branch though identical on time and allocation. Rule knobs now read a JSON bool as happily as 0 or 1.
FR0029's tail extraction now waits for the COMPILER: FS3511 is emitted at codegen where no analyzer can see it, but the apply tool builds before it rewrites and the warning carries the builder's own position, so those lines are handed to the rule and `runTail` is offered where the dynamic fallback is real. Absent that warning the bar is `tailLines`, raised from 10 to 40 - a shape unwieldy on its own merits, since a smaller resumable body is not a goal in itself. Below the bar the rule now says NOTHING: a note about code that has no problem helps nobody, so it is a quickfix or silence. Hoisting plain lets and splitting branches move code that already existed, name nothing new, and stay fixes either way. FR0065 gained two offers beside the Tls12 swap - comment the dead protocol out of the flags keeping the live one, or comment the whole setting out and let the OS negotiate - and `{ "FR0065": { "dropLegacyProtocols": true } }` lets an unattended run apply the first; `--api-changes` is deliberately NOT the gate, since retiring a protocol changes what the wire negotiates rather than what callers compile against. Protocol detection now reads `[<Obsolete>]` beside the curated list, because the framework marks its own inconsistently: SslProtocols.Tls11 carries the attribute and SecurityProtocolType.Tls11 - the one real code sets - does not, a decade after TLS 1.1 was deprecated. FR0028 no longer reports the cure as the disease: `let chunked = Array.chunkBySize 200 ids` followed by `for batch in chunked` is deliberate batching, and the guard had only ever looked inside the loop header. FR0015 rewrites a literal-pattern `Regex.Replace(s, "abcd", "x")` to `s.Replace("abcd", "x")`, declining wherever the two differ - measured: a `$` in the replacement is substitution syntax to one and text to the other, and an empty pattern makes String.Replace throw where Regex inserts between every character.

## 0.8.8

a fix can be applied to a standalone script at last. The .fsx safety net asked whether the REWRITTEN script still had a typecheck context, and readScript answers None both for a script carrying any error and for one with no #load at all - so the rollback condition was already true before any edit, and every fix to such a script was applied and put straight back, on every run, forever.
